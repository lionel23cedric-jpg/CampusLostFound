# Explainable Item Matching Evaluation

## Purpose and AI-enhanced classification

Campus Find uses a transparent rule-based matcher plus an actual pretrained
sentence-embedding model, `Xenova/all-MiniLM-L6-v2` at revision
`751bff37182d3f1213fa05d7196b954e230abad9`, running locally with
Transformers.js 4.3.0. The model compares public Lost and Found report wording;
it is not a chatbot or an external generative-AI service. If the model is not
available, the original deterministic matcher still works and the interface
labels that result as a rule fallback.

This evaluation covers item matching only. The other four bounded AI-assisted
functions are documented in [AI Feature Suite](ai-feature-suite.md).

The feature supports a person's decision; it does not approve ownership or
complete a recovery automatically. A user must inspect a suggestion and use the
separate Claim workflow, where private verification evidence is checked.

## Public input data

Only information already permitted in member-facing report responses is scored:

- title and public description;
- category;
- public campus location, when the reporter allows it;
- event date, when the reporter allows it;
- colours and tags.

Private verification answers, reporter identity, contact details, serial
numbers, private notes, and exact private locations are excluded.

## Scoring algorithm and weights

For one open report, the service selects up to 500 open, visible reports of the
opposite type that belong to other users. Each candidate receives up to 100
points.

| Public factor | Maximum points | Method |
| --- | ---: | --- |
| Category | 25 | Exact category identifier |
| Location | 15 | Exact public campus-location identifier |
| Date | 15 | Same Pacific/Auckland calendar date: 15; within 3 calendar days: 12; within 7: 8; within 14: 4 |
| Colours | 15 | Jaccard overlap after case and Unicode normalisation |
| Tags | 10 | Jaccard overlap after case and Unicode normalisation |
| Text | 20 | Baseline: cosine similarity of term frequencies; model-assisted: cosine similarity of mean-pooled, normalised MiniLM embeddings |

Positive factors are returned with short explanations such as `Same category`
or `Dates are within 3 days`. Candidates below 35 points are not shown. The five
highest remaining candidates are returned in score order with deterministic
tie-breaking.

The current model shortlist admits a candidate with either at least 35 rule
points or at least 15 non-text points. The latter is the minimum from which the
model's maximum 20 text points could reach the final 35-point threshold. At
most 30 eligible candidates are sent to the local model. Its score replaces
only the existing text factor, after which candidates are reranked and checked
against 35 again. Category, location, date, colours, and tags retain their
fixed weights. No embedding or private evidence is returned to the browser.
Model failures restore the original rule ranking over all queried candidates,
not a partial AI list.

## Independent labelled dataset

The committed evaluation set contains 12 synthetic source scenarios and five
opposite-type candidates per source, for 60 comparisons. No record came from
the project database or a real person. Each scenario labels two candidates as
relevant: a clear match and a harder variation with a synonym, a missing public
field, or a wider date gap. The other candidates include same-category,
same-location, and unrelated distractors.

The dataset therefore contains 24 labelled matches and 36 labelled non-matches.
It covers chargers, drink bottles, ID cards, keys, bags, earbuds, umbrellas,
books, glasses, wallets, clothing, and cycling equipment.

## Decision threshold

The production and evaluation threshold is 35 out of 100. A comparison with a
score of 35 or more is predicted as a possible match. This deliberately favours
recall: missing a genuine recovery opportunity is costly, while the interface
can present a small number of explainable suggestions for human review.

September 2026.

| --- | ---: |
| Precision | 0.828 |
| Recall | 1.000 |
| F1 score | 0.906 |
| Accuracy | 0.917 |
| Top-match accuracy | 1.000 |

| Actual / predicted | Match | No match |
| --- | ---: | ---: |
| Match | 24 | 0 |
| No match | 5 | 31 |

Under the older, rule-qualified model gate on 22 September 2026, the local
model produced the same aggregate matrix as the rule baseline: 24 true
positives, 5 false positives, 0 false negatives, and 31 true negatives. This
is a historical result, not an evaluation of the current shortlist.

On 10 October 2026, `npm run evaluate:matching:ai` was rerun with the current
production eligibility rule on the same 12 synthetic cases and 60 comparisons.
The measured results were:

| Measure | Current model-assisted result |
| --- | ---: |
| Precision | 0.571 |
| Recall | 1.000 |
| F1 score | 0.727 |
| Accuracy | 0.700 |
| Top-match accuracy | 1.000 |

| Actual / predicted | Match | No match |
| --- | ---: | ---: |
| Match | 24 | 0 |
| No match | 18 | 18 |

All 12 sources still placed a labelled relevant candidate first, and all 24
labelled matches crossed the threshold. However, 18 distractors also crossed
it, up from 5 under the narrower gate. The broader shortlist can recover a
low-lexical candidate that the earlier gate would never embed, but this fixture
shows a substantial precision cost. These synthetic results are **not evidence
of improved matching accuracy or a prediction of real-campus performance**.

## Error analysis

The current 18 false positives often have some shared public structure and
semantically similar but non-identical wording. With a low recommendation
threshold, the model can lift such distractors over 35 even when the rule score
alone would not. This is why a score is presented only as a suggestion and why
the Claim verification step remains separate. Choosing a stricter gate based
only on these 60 synthetic pairs would risk overfitting; a larger independently
labelled set is needed before changing the threshold responsibly.

No false negatives appeared in this small synthetic set. That is encouraging
but does not establish the same recall on real campus language, spelling errors,
rare categories, or reports with several hidden fields.

## Privacy and ethics

- Inference uses the model packaged with the application; report text is not
  sent to an external AI provider.
- Only public report fields are used.
- Explanations contain bounded factor descriptions rather than private input.
- The algorithm does not infer identity or decide ownership.
- The synthetic evaluation contains no personal or operational campus data.
- Users and staff retain responsibility for reviewing suggestions and evidence.

## Limitations

- The labelled set is intentionally small and synthetic, so its metrics are
  evidence for repeatability rather than a claim of production accuracy.
- The synonym list is short and English-focused.
- Exact category and location identifiers receive substantial weight.
- Photos are not analysed by this matching algorithm. The separate, optional
  image-category assistant analyses only the first image selected by a member
  after an explicit click.
- The score is not learned from outcomes and does not adapt automatically.
- The model is English-focused; the synthetic fixture is too small to validate
  real-world accuracy, multilingual wording, or fairness. The 30-candidate
  shortlist may omit a relevant low-structured-score report, while its current
  broad eligibility can show more false positives.
- If a packaged model file is unavailable or local inference fails, matching
  continues using only the baseline rules.
- A future study could use consented, anonymised labels and compare thresholds,
  but that is outside the current course-project scope.

## Reproduction command

From the `web` directory, run:

```powershell
npm run evaluate:matching
npm run evaluate:matching:ai
```

The first command verifies the deterministic baseline. The second loads the
packaged quantized model, runs real local inference on the same synthetic
fixture, and prints its measured confusion matrix and metrics. The model files
are included in Git and the source ZIP so the test is reproducible without a
runtime download. The model is published under the [Apache 2.0 licence](https://huggingface.co/Xenova/all-MiniLM-L6-v2);
see the [Transformers.js pipeline documentation](https://huggingface.co/docs/transformers.js/pipelines)
for the feature-extraction API.
